## MODIFIED Requirements

### Requirement: 直接編輯文件標題

系統 SHALL 在文件 H1 只顯示頁面標題，類型以中文標籤另行呈現。使用者 SHALL 能直接編輯 H1 標題：Enter 或失焦保存、Escape 取消；空白或超過 200 字元 MUST 不送出並恢復原標題且顯示原因；保存失敗 MUST 恢復原標題並顯示錯誤。保存成功後側欄、麵包屑與瀏覽器標題 SHALL 同步更新。 較早保存回應 MUST 不覆蓋使用者後續輸入。

#### Scenario: 直接改名
- **自動化驗證**: `UX-03`；Playwright（連接本機測試服務）：點擊 H1 輸入新標題後按 Enter，斷言 H1 文字不含「筆記 」或「日記 」前綴、API 回傳新標題、側欄目前項目與麵包屑同步更新、重新整理後保留；另以 Escape 斷言未送出請求且恢復原值。
- **WHEN** 使用者點擊標題並輸入新名稱
- **THEN** Enter 後標題保存並在各處同步更新，Escape 則恢復原標題

#### Scenario: 無效或失敗的標題
- **自動化驗證**: `UX-04`；Playwright：清空標題後失焦、輸入 201 字元、攔截請求讓 title API 回應 500，三種情況皆斷言 H1 恢復原標題並顯示 `role="alert"` 原因。
- **WHEN** 使用者送出空白、過長標題，或保存失敗
- **THEN** 系統不保留無效值，恢復原標題並說明原因

### Requirement: 換頁保留未上傳的修改

系統 MUST 在站內換頁前保存目前頁面的本機修改；回到該頁時 SHALL 保留修改並完成雲端保存。 上一頁／下一頁 MUST 等待草稿保存，失敗保留目前文件；未下載正文的 metadata 不得冒充本機草稿；啟動失敗 MUST 釋放資源。

#### Scenario: 輸入後立即換頁
- **自動化驗證**: `UX-19`；Playwright：在甲頁輸入文字後不等雲端確認立即切到乙頁，再返回甲頁，斷言文字仍在並顯示雲端已儲存；以新的瀏覽器 context 開啟甲頁斷言伺服器已保存該文字。
- **WHEN** 使用者輸入後馬上切換頁面
- **THEN** 修改不遺失並最終保存到雲端
