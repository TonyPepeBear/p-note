# Design

## Context

動機見 [proposal.md](proposal.md)。目前 `navigate` 依序等待草稿保存與入口 HTML 查詢才派送導覽事件；`App` 清除 session 後先讀頁面 API，再呼叫 `start` 載入 IndexedDB。`start` 已支援下載過的文件不等 WebSocket，但仍位於 API 之後。`Editor` 已有連線前 `checkAccess`、本機保存與持久確認機制，可延伸使用。

本變更跨導覽、文件載入與同步生命週期，涉及尚未驗證文件的寫入隔離，因此需要本設計。現有 workspace-usability 的 UX-20 與 UX-21 由 delta 更新；realtime-sync 與 personal-auth 的伺服器授權、離線草稿及版本隔離要求持續適用。

## Goals / Non-Goals

**Goals:**
- 將本機可讀／可寫與雲端可同步拆為獨立狀態；網路等待不位於已下載頁面的顯示路徑。
- 跨非同步邊界保留目前導覽識別，驗證結果只作用於對應文件。
- 使用可控制請求釋放的測試證明未依賴網路，另對小型 fixture 設定 500 毫秒切頁預算。

**Non-Goals:**
- 不增加記憶體中多個常駐編輯器、背景多頁同步或預抓所有頁面。
- 不變更離線新增、改名、階層與圖片上傳的連線限制。
- 不將首次資源下載、冷啟動或大型文件宣稱為固定 500 毫秒；本機優先不能繞過已知登出／失效狀態。

## Decisions

### 1. 本機載入與背景驗證分離

導覽先保存舊頁草稿，再切換路由。從現有 owner／page／generation 索引定位文件，確認已下載且正文可讀後以不連線的 provider 建立 session。頁面 API 在背景驗證登入、所有權、刪除與 generation；相同 scope 才啟動同步，更新 metadata 時保留同一編輯器。今天入口使用既有台北日期映射，無今日對應則走 API。

不使用只有 metadata 的快取當成空白正文；本機資料損毀走線上回退，離線明確提示。owner 索引只用於裝置快取定位，不構成伺服器授權；已知失效狀態禁止重新啟動樂觀編輯，成功登入後以伺服器身分重新選擇快取。

替代方案是維持 API 優先再隱藏提示，無法移除網路延遲；常駐多文件則增加生命週期與資源管理，本次不採用。

### 2. 以單一驗證結果控制同步

沿用 `checkAccess` 及重試流程，避免 App 與 Editor 重複做同一輪頁面驗證。首次背景驗證由目前 session 共用；重連仍重新驗證。provider 必須保持 disconnect，直到驗證通過，涵蓋一般 Yjs update、握手與自訂 commit，不只攔截持久確認訊息。

驗證等待時允許本機保存，顯示同步中而非連線失敗。暫時網路／500 錯誤保留本機編輯與既有重試退避；明確無效則先停止編輯、保存當下 doc，再進入登入或草稿保護畫面。若此時本機保存失敗，保留該 doc 與可見文字、提示失敗，不可先銷毀後重新載入舊快取。不要用驗證前快照取代期間的新輸入。

替代方案是先建立同步連線再靠伺服器拒絕，會把舊版本更新送出，不符合本次草稿邊界。

### 3. 版本檢查改為背景工作

每次站內換頁仍檢查入口版本，但不阻塞路由派送。維持有界逾時與失敗降級。發現新版時以目前最新導覽序號決定是否處理；過期結果不直接重導舊頁。有效新版結果在當下草稿保存完成後再確認導覽序號並載入最新目標；保存期間防止額外輸入落在保存邊界之外，保存失敗恢復操作且不重新載入。保留新頁命名等路由語意。

替代方案是取消版本檢查或定期檢查，會更改既有更新保證；本次只移出顯示關鍵路徑。

### 4. 導覽取消與資源清理

所有本機開啟、API、驗證與版本結果帶入導覽序號及 scope；過期結果只清理自己的資源，不改動目前頁面。離開時保存舊頁、停止 provider，再釋放 cache／doc；延遲完成的 start 也必須清理。驗證成功不重建同 scope 編輯器，以保留焦點、選取與輸入法狀態。上一頁／下一頁同樣執行草稿保存與過期檢查。

不以保留可編輯舊畫面掩飾新頁等待，以免文字寫入錯誤文件。

## Risks / Trade-offs

- 本機 metadata 暫時過期 → 背景校驗後更新；標題與頁面操作仍以伺服器授權為準。
- 網路驗證前看見已快取私人內容 → 沿用離線文件的裝置信任邊界；已知登入失效不繞過登入，快取不跨擁有者，伺服器持續獨立授權。
- 非同步失效處理遺失剛輸入文字 → 保存目前 doc，寫入失敗保留記憶體內容，不先卸載。
- 多重驗證與版本結果互相覆蓋 → scope 與導覽序號檢查、可控制亂序測試及有效連線數斷言。
- 絕對時間測試受機器負載影響 → 固定小型 fixture，同時以尚未釋放網路的事件屏障證明核心行為；保留 trace 排查超時，不放寬門檻掩蓋等待網路。

## Migration Plan

不修改既有快取格式或伺服器資料結構。完成相關 Chromium TDD 後跑完整三瀏覽器驗收與既有隔離／離線回歸，再依專案流程部署及自動提交實作。回退可重新部署舊版前端，既有 IndexedDB 草稿保持可讀；本次規劃階段不部署。
