# Design

## 版本資料

版本目錄放在 D1，完整落盤 Yjs 快照放在 BACKUPS bucket 的獨立前綴。每個版本固定記錄擁有者、頁面、標題、時間、來源、快照校驗資訊與同步世代。版本目錄必須在快照成功持久寫入後才發布。首次編輯前建立基準版本，連續編輯的自動快照最多每五分鐘建立一份，開啟歷史再補存最新內容；相同快照去重，手動及還原前版本不受五分鐘限制。清單使用穩定排序及游標，避免同毫秒版本漏失。不得從會被 compact 清除的 updates 反推歷史。

版本功能適用一般筆記與日記，還原範圍只有標題及正文。保留階層、日記日期、資料庫欄位值及其他頁面。版本歷史不設定隱藏到期清除機制，未有舊快照的既有頁面從功能啟用後開始累積。

## 還原與同步

還原使用持久操作識別去重並協調既有結構與整站還原鎖。先暫停舊房間並保存還原前版本，再於新世代 prepare 目標快照，原子切換標題與世代後恢復服務及搜尋索引。失敗保留操作狀態讓同一請求重試，不得反覆覆蓋還原後的新編輯。舊世代同步端由現有權限檢查與本機草稿隔離保護。

## 介面與權限

使用 Mantine 提供手機可操作的版本歷史面板，列表、預覽、建立及還原狀態分開處理。預覽使用 BlockNote 唯讀視圖，不可將預覽寫入目前文件。還原需由使用者確認，成功載入新世代；依賴網路的操作離線停用並提示。讀寫入口沿用 session、Origin、擁有者及可見性檢查，不放寬 API key/MCP 權限。

## 驗證

先以相關 Chromium E2E 取得因功能缺漏而失敗的 Red，再完成實作並跑同 spec 的 Green／Refactor。驗收執行三瀏覽器、Workers、型別、建置及 OpenSpec 驗證，覆蓋歷史持久性、格式預覽、還原保護與失敗重試。
