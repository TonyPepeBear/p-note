# Design

狀態：技術方向與設計提案，不是已完成的實作。決策以 [需求整理](../../../docs/v1-scope.md) 為準；已授權本機測試環境與 BlockNote／持久化／離線重連 TDD。

## Context

已建立本機技術原型與測試環境，未建立雲端資源或部署。動機與能力範圍見 proposal.md。已確認 React＋Vite、Better Auth＋magic link、Yjs、Durable Objects＋y-partyserver；BlockNote 0.55.0 已通過此次自動化技術驗證。Cloudflare Workers Paid plan 是設計前提，備份保留 90 天。

## Goals / Non-Goals

**Goals:**

- 每種資料有明確原始來源，不以 D1 JSON 與 Yjs 同時寫入內文。
- 定義已保存、重連、刪除、還原與備份的可觀察承諾。
- 先辨識整合與跨儲存限制，再驗證核心假設。

**Non-Goals:**

- 此次技術驗證不實作正式登入、頁面資料結構、私有資產、備份或部署。
- 第一版提案不建立團隊權限、資料庫視圖、完整歷史時間軸或整站同秒快照。
- 不自行發明 Yjs 協定，也不承諾 CRDT 能保留所有互相矛盾的編輯意圖。

## Decisions

### 1. 技術方向

React＋Vite 已選定；採 TypeScript。BlockNote 以 Playwright 自動驗證中文 composition、手機模擬觸控、圖片、程式碼與離線編輯（V1），不要求人類操作實際手機。Better Auth 管理 magic link／session；寄信先評估 Cloudflare Email Service（Q3），不使用 Access。

Yjs 取代整篇 JSON 版本衝突提案。整篇樂觀鎖較簡單，但不符合已確認的即時同步方向；其他同步平台不作為預設方案。

### 2. 原始資料與概念結構

| 位置 | 概念資料 | 責任 |
| --- | --- | --- |
| D1：Better Auth 管理的表 | 使用者、session、驗證資料 | 登入原始來源，不另建重複機制 |
| D1：pages | id、owner_id、kind、title、parent_id、journal_date、sync_generation、metadata_revision、created_at、updated_at、deleted_at | 頁面與結構原始來源；未建立 schema |
| D1：搜尋資料 | 純文字、摘要、indexed_generation、indexed_checkpoint | 由 Yjs 重建，舊檢查點不能覆蓋新索引 |
| D1：assets | id、owner_id、object_key、original_name、mime_type、byte_size、checksum、created_at | 圖片索引與所有權 |
| 每頁的 SQLite-backed DO | 房間狀態、Yjs 快照、更新紀錄、提交確認／檢查點 | 內文原始來源 |
| 私有 R2 | 不覆寫的圖片原檔 | 檔案原始來源 |
| IndexedDB | 以使用者、頁面、世代隔離的 Yjs 狀態與待確認提交 | 原裝置狀態，不是雲端備份 |

標題留 D1 且需連線，不加入內文 Yjs。日記日期是選定日期，建立／更新時間另存時間戳；日記時區 Asia/Taipei；垃圾桶同日期日記仍保有唯一性。

上層必須同屬擁有者、是有效筆記且不能形成循環。日記唯一性需由後端保證，兩台同時建立取得同一篇。中文搜尋品質另驗證。

### 3. 房間與持久保存

以穩定擁有者 ID、頁面 ID 與同步世代路由房間；一般編輯不換世代，備份覆蓋還原或不相容資料替換才換。

寫入提案：驗證 session／擁有者／房間狀態／世代與資料限制，持久寫入更新紀錄，再確認提交及廣播。確認涵蓋刪除與格式變更，不只依 state vector 相同判斷。保存失敗不回報成功；確認舊提交不能把其後的新修改一起標成已保存。

快照整理以固定檢查點為界，原子保存快照與移除已包含紀錄，未包含的新更新保留。成功保存但回應遺失時，重送／重複更新仍能完成確認。

y-partyserver 的 onLoad／onSave 不證明預設廣播順序符合承諾。V2 已在本機驗證掛鉤、確認識別、同時更新、休眠／喚醒、重啟與整理。若無法達成，修訂適配或設計，不降低已保存語意。

首版提案不只依靠延後全量快照，避免已廣播但未保存的區間。採更新紀錄後再整理，整理門檻依實測決定。

### 4. 登入與連線

固定登入期限為 30×24 小時、不續期。magic link 單次使用、有效 10 分鐘；同 Email 每 60 秒一次／15 分鐘最多 5 次，同 IP 每 15 分鐘最多 20 次（Q4）。擁有者 Email／寄件設定待 Q3。owner_id 來自伺服器 session，不接受用戶端宣告。

連線建立與維持期間處理 session 到期／撤銷、頁面刪除與世代失效；只在建立 WebSocket 時驗證不足。具體阻擋與關閉機制列入 V2／V3。

已接受伺服器可讀內文，由登入與所有權保護；第一版不採端對端加密。

### 5. 本機保存與重連

先載入本機狀態，再接同世代房間交換缺少更新。待確認提交繼續追蹤；本機與雲端保存狀態分開。確認後保留完整本機狀態作快取。

只支援已下載頁面內文離線編輯，新增頁面、標題／結構／上傳需連線（Q5 已決定）。退避重連，前景／網路恢復時重查 session、刪除狀態與世代。關閉前最後送出不是唯一保存機制；無快取頁面不可冒充離線可用。

可沿用 provider 分頁同步，但不跨使用者／世代共用狀態。舊世代本機內容先隔離供檢視或另存，不直接套用到新世代。

### 6. 跨 D1／DO 結構異動

兩者沒有共同原子交易。刪除／世代切換提案採可重試分階段操作：相關房間先停止更新，再變更結構，兩側完成前不回報成功。失敗保留可辨識中間狀態，重試或恢復；不得離線復活頁面（V3）。

階層、同日建頁、垃圾桶與還原規則由後端維持，不交給內文 CRDT 副作用決定。

### 7. 圖片

由已驗證 session 的 Worker 上傳／讀取私有 R2。前後端驗證格式、大小與實際內容（JPEG／PNG／WebP／GIF，每檔最多 10 MiB，不壓縮；拒絕 SVG／HEIC）；不以檔名或難猜網址當授權。成功上傳後才產生正式文件引用。

圖片識別穩定且不覆寫。失敗可能留下未引用檔案，首版提案不自動永久清理，以免誤刪本機或備份引用；垃圾桶不刪原檔。

### 8. 備份與還原

保留 90 天已確認。每日台北 03:00（UTC `0 19 * * *`），設定頁下載 ZIP／選擇成功備份覆蓋還原。備份區為獨立私有 R2 bucket，另提供可下載完整匯出。

固定 D1 頁面清單與階層快照，再取得對應世代的持久 Yjs 狀態。記錄逐篇檢查點與時間；世代途中改變時重試或使備份失敗，不拼接不相容文件。這是時間窗備份，不是整站同秒快照（Q8）。

清單引用 Yjs 二進位檔、metadata 與必要圖片副本，記錄版本、大小與校驗值。全部通過才成功；失敗嘗試不取代最新成功備份。成功時間起滿 90×24 小時到期；仍被保留備份引用的圖片不得清理。

產品備份排除 session、magic link 憑證與服務密鑰；穩定擁有者 ID 必須映射有效帳號。搜尋可重建。平台 D1／DO 時間點復原不是 90 天產品備份或圖片副本的替代品。

覆蓋還原：檢查備份 → 備份現況 → 暫停寫入 → 新世代準備／驗證資料與圖片 → 切換正式資料 → 關閉舊房間。中途失敗不發布半套還原。舊修改只能檢視或另存；V4 須以程式在乾淨儲存完整還原並比對資料／圖片，不要求人工操作。

### 9. TDD 與全自動驗收

依新 AGENTS.md，採 Red → Green → Refactor。每個 Scenario 指定唯一測試 ID，先建立可執行的失敗測試，再寫最小實作；重構後相關測試持續通過。測試環境建立與規格文件修改以自動化命令驗證，不把缺套件、語法錯誤當有效 Red。

規劃採 Vitest 單元、Cloudflare 官方 Workers runtime 整合與 Playwright 端到端。保存與恢復測試使用真正隔離的 D1／DO／R2 與 WebSocket，透過官方 eviction／abort 及邊界故障注入測試中斷，不用純記憶體 mock 證明持久化。寄信用機器可讀測試寄件匣，日期與 90 天保留使用可控時鐘。

手機採 Chromium／WebKit 模擬、觸控與 viewport 斷言；中文採 composition／input fixture。這些不等於原生 OS 鍵盤與輸入法，限制明確記錄，不另設人工驗收。全部自動化方法、ID 對照、結果證據與未覆蓋限制見 [驗證計畫](../../../docs/automated-validation.md)。

Q1–Q9 是產品契約與部署輸入，輸入確定後由機器驗證完整性與一致性；V1–V4 全部透過自動化測試。未決值保留草案，不以測試報告代替產品選擇。完整 spec ID 與測試結果比對不得把 skip／todo／未執行算通過。

規格修改與完成開發後各自自動 commit。本次先提交規格，接著建立自動化環境與技術驗證；只完成此次範圍的任務，不宣稱完整產品驗收。

### 10. 已驗證的本機適配

原型在 YServer.onMessage 先解析原生 Yjs sync step 2／update 或含提交 ID 的完整狀態，候選文件驗證通過才寫入 SQLite；等待 storage.sync 後確認並交回套件廣播。更新與快照用 SQLite 表保存，整理交易只刪已含檢查點以前的紀錄，最高檢查點同時考慮快照與更新表。原生廣播基線、純刪除、寫入失敗、重送、abort、eviction、整理中斷及損毀載入均有自動化證據。

IndexedDB 以 owner／page／generation 雜湊名稱隔離。y-indexeddb 9.0.12 未回報逐筆交易完成與寫入失敗，因此保留載入，停止其預設更新寫入，改由明確交易合併舊快取與保存完整狀態。原型掛鉤固定版本並在升級前重驗。關閉 BroadcastChannel，避免以分頁直接交換掩蓋服務保存故障；離線刷新另用靜態 Service Worker 快取。

原型尚未有正式 session、資料所有權或世代切換；只接受本機入口，不能據此把正式 AUTH／ASSET／BACKUP 算通過。具體結果、版本、TDD 證據與限制見 [技術驗證](../../../docs/tdd/README.md)。

## Risks / Trade-offs

- [廣播可能早於 onSave] → V2 證明保存先於確認，不把 provider synced 當落盤證據。
- [CRDT 收斂不等於保留所有意圖] → 驗證同區塊刪改、移動、格式，不宣稱永不丟失意圖。
- [D1／DO 操作中斷] → V3 驗證中斷與重試，完成前不回報成功。
- [本機資料被清除／容量不足] → 明確顯示保存失敗，未上雲內容不在備份保護範圍。
- [圖片與 Yjs 狀態累積] → 實測整理與大小界線，首版不做不安全的永久清理。
- [備份仍在同一服務帳號] → 提供完整下載，帳號外目的地尚未設定。
- [備份有時間窗] → 清單記錄界線，Q8 決定是否接受。
- [手機與中文事件模擬不含原生 OS 行為] → 以明確自動化斷言驗收應用介面，記錄未覆蓋範圍，不加入人工測試門檻。
- [技術原型尚無正式登入] → 原型 Worker 僅接受本機入口，禁止對外部署，後續登入整合完成前不作產品使用。

## Migration Plan

目前沒有既有產品資料，不執行 migration 或部署。獲授權後先完成 Q 決策與 V 驗證，再建立 schema 與環境。

部署前自動測試保存、重連、備份與還原；升級保留舊 Yjs 可讀性並驗證跨版本裝置。回滾不能重建空文件或清除已確認紀錄；不相容候選版本先不切換，修訂 change。
