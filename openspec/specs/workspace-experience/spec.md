# workspace-experience Specification

## Purpose
讓個人筆記與日記應用提供清楚、美觀且一致的操作介面，使登入、寫作、查找、日記回顧與備份管理可被直接理解，並兼顧桌面閱讀、手機觸控、鍵盤操作及既有資料保護。

## Requirements

### Requirement: 清楚登入與寫作工作區

系統 SHALL 以 Notion 式的中性色、精簡導覽及白色無框文件作為全站設計基準；登入、確認登入、桌面及手機工作區 MUST 使用一致字級與控制項。PWA 安裝、更新與說明浮層 SHALL 使用相同視覺，安裝圖示與瀏覽器主題色 SHALL 配合中性工作區。桌面側欄 SHALL 支援收合與恢復，且不改變目前文件或已輸入內容；手機 SHALL 提供可觸控導覽而不壓縮正文。側欄與手機導覽 SHALL 不常駐「新增筆記」與「新增資料庫」按鈕；側欄與手機導覽的「私人頁面」標題旁 SHALL 提供單一「＋」入口，與頂端工具列共用按需展開的新增選單；桌面收合側欄及手機仍可建立最上層筆記或資料庫。新增選單 MUST 支援鍵盤、Escape 返回觸發點、手機 44px 觸控、失敗重試與還原鎖定，並保留目前草稿及新筆記標題選取。

#### Scenario: 登入頁與確認流程
- **自動化驗證**: `UI-01`；Playwright 檢查登入用途、Email、唯一主要登入動作、寄送與確認狀態、手機主要操作至少 44px 及無水平溢出。
- **WHEN** 未登入使用者開啟網站、寄送登入連結並進入確認頁
- **THEN** 各步驟以一致的精簡版面呈現目前狀態及下一步，錯誤保留可重試入口

#### Scenario: 正文優先的響應式工作區
- **自動化驗證**: `UI-02`；Playwright 斷言中性緊湊側欄、白色無框正文、收合與恢復後內容保留、375px 無溢出、手機 44px 主操作及新增後繼續編輯；UI-CREATE-01～04 斷言側欄／手機導覽無常駐新增筆記及新增資料庫文字按鈕、工具列選單按需出現、收合與設定仍可新增、鍵盤與 Escape 焦點、建立最上層筆記及資料庫、保留草稿與失敗重試；UI-CREATE-05 斷言私人頁面標題旁加號可建立最上層筆記與資料庫，鍵盤取消焦點返回加號，手機取消保留導覽且建立後關閉導覽、觸控區至少 44px；BACKUP-UI-LOCK-01 斷言還原期間兩種新增入口停用。
- **WHEN** 使用者在桌面收合與恢復導覽，或在手機使用導覽切換及新增筆記
- **THEN** 目前頁面與正文保持可用；桌機導覽緊湊且文件有閱讀空間，手機關閉抽屜後可立即編輯，管理介面不得把正文擠出首屏

### Requirement: 管理入口與清楚操作範圍

系統 SHALL 將搜尋、日記、頁面操作、垃圾桶、備份及 API key 放在一致且有名稱的介面；右上角與側欄每個頁面的「⋯」SHALL 顯示一致的動作列表；側欄右鍵 MUST 開啟該頁選單且不切換正文。選單 MUST 支援鍵盤、Escape、外部點擊關閉、有效焦點返回及手機觸控；還原鎖定時 MUST 禁止選單操作。重新命名、移動及刪除確認 MUST 明確操作選定頁面，修改其他頁面不得誤改目前文件，移動選項 MUST 排除目標及後代。設定頁 SHALL 保留工作區導覽與原文件 context。關閉浮層或返回文件 MUST 保留草稿與有效焦點；從設定選擇其他頁面 MUST 正確開啟所選文件。備份還原執行中或中斷待重試時 MUST 鎖定會離開還原流程的入口，並保留原備份及原 request ID。設定期間若背景驗證收到 401，系統 MUST 離開設定、立即隱藏已顯示的 API key、顯示重新登入介面並保留文件草稿。

#### Scenario: 搜尋與日記回顧面板
- **自動化驗證**: `UI-03`；Playwright 斷言搜尋／日記面板、結果與空狀態、Escape 焦點返回、選擇結果後開啟原頁，以及手機無重疊抽屜。
- **WHEN** 使用者搜尋筆記、選擇日記日期或月份，或取消面板
- **THEN** 輸入、結果、載入與錯誤層次清楚；選擇後返回文件，取消不改變正文且焦點返回可操作位置

#### Scenario: 頁面操作與垃圾桶
- **自動化驗證**: `UI-04`；Playwright 斷言重新命名／階層、長標題不溢出、右上角呈現列表且無頁面操作彈窗、側欄點擊及右鍵不換頁、選單鍵盤／Escape／外部關閉與手機觸控、其他頁面改名／新增子頁／新增子資料庫／移動及排除後代、失敗可重試、刪除確認目標、取消保留及垃圾桶還原回饋。
- **WHEN** 使用者由右上角、側欄「⋯」或側欄右鍵開啟動作列表，修改所選頁面資訊、移動頁面或管理垃圾桶
- **THEN** 先呈現精簡動作列表，選擇重新命名或移動後才開啟對應表單；開啟選單及修改其他頁面保留目前正文，危險動作說明所選目標與可還原方式，取消不刪除，完成與失敗有可辨識回饋；刪除目前頁面或祖先時安全返回今天

### Requirement: 一致編輯與備份呈現

系統 SHALL 將正文、資料庫、備份、API key 及其浮層全部套用共用的字級、間距、色彩與狀態規則。資料庫 SHALL 使用可鍵盤操作的檢視分頁與相鄰工具列；主要功能 MUST 可完成多步操作、可鍵盤操作且適合手機觸控。備份還原進行中或中斷待重試時，瀏覽器返回 MUST 保留目前設定與網址、隱藏文件並沿用原還原請求；設定期間的全域錯誤 MUST 在備份及 API key 頁保持可見且可關閉。

#### Scenario: 編輯工具與私人圖片
- **自動化驗證**: `UI-05`；Playwright 斷言圖片及區塊操作、保存失敗重試、資料庫檢視 tabs 的選中與鍵盤切換、搜尋清除，以及資料庫新增筆記／編輯／返回後內容與列保留。
- **WHEN** 使用者編輯正文、插入圖片，或在資料庫切換檢視並開啟或新增筆記
- **THEN** 畫布以內容為主，工具與 properties 緊鄰其內容；表格僅在自身容器捲動，檢視切換與編輯往返不遺失資料

#### Scenario: 備份空狀態與還原確認
- **自動化驗證**: `UI-06`；Playwright 斷言設定頁保留導覽、備份／API key 切換後返回原文件與內容、設定中選擇其他筆記、備份建立／下載／還原確認，以及 API key 建立／撤銷流程；BACKUP-UI-LOCK-01 斷言還原執行中與中斷後的離頁入口及瀏覽器返回鎖定、原網址與備份保留及相同 request ID 重試；UI-06-ERROR 斷言備份及 API key 頁的側欄登出與今天儲存失敗提示可見、可關閉且設定保留；KEY-03 斷言設定期間背景 401 後立即隱藏 key、離開設定、顯示重新登入並保留草稿。
- **WHEN** 使用者從文件進入備份或 API key 設定、切換設定、執行或重試還原，或設定期間登入失效
- **THEN** 正常設定操作保留導覽及原文件 context；還原執行中與中斷待重試時不能由返回、瀏覽器歷史導覽、側欄或登出入口離開流程，重試沿用原備份及 request ID；背景登入失效立即離開設定並隱藏 key，重新登入提示與保留草稿可見；設定期間側欄失敗仍顯示可關閉的全域錯誤；空資料、載入、錯誤與重試有一致呈現，備份覆蓋及 key 撤銷仍需清楚確認

### Requirement: 一致且可讀的互動色

系統 SHALL 在淺色工作區使用柔和中性的互動底色；目前項目、主操作及危險操作 MUST 保留可辨識語意。停用元件 MUST 不呈現可操作的 hover，鍵盤焦點 MUST 可見；觸控裝置 MUST 不留下黏住的滑鼠 hover。

#### Scenario: 中性操作與主操作 hover
- **自動化驗證**: `UI-07`；Playwright 斷言登入、工具列、備份與設定 hover 背景維持淺色、中性底色一致、hover 與預設不同、文字對比至少 4.5:1，主操作保留白字與可讀性。
- **WHEN** 滑鼠移至中性操作或主操作
- **THEN** 中性操作顯示柔和淺底、文字清楚；主操作維持全站一致的強調色與 hover 回饋

#### Scenario: 側欄選取與互動狀態
- **自動化驗證**: `UI-08`；Playwright 斷言未選取與選取項目 hover 均有回饋、aria-current 選取標記與文字對比保留；觸控操作後未選取項目不殘留 hover。
- **WHEN** 使用者以滑鼠或觸控操作側欄
- **THEN** 未選取、選取與 hover 可區分，目前頁面持續標記

#### Scenario: 選單與編輯器互動一致
- **自動化驗證**: `UI-09`；Playwright 斷言區塊選單及 BlockNote 工具 hover 使用一致淺色背景、文字對比至少 4.5:1；危險操作維持紅色及可讀性。
- **WHEN** 使用者操作區塊選單或編輯器工具
- **THEN** 互動色與工作區一致，刪除類動作保留紅色語意

#### Scenario: 停用與鍵盤焦點
- **自動化驗證**: `UI-10`；Playwright 斷言停用上傳與還原操作在 pointer 移入後背景不變、保持 disabled、確認啟用後還原按鈕對比至少 4.5:1；鍵盤 Tab 焦點有可見 outline 且能操作面板。
- **WHEN** 元件尚不可操作或使用者以鍵盤移動焦點
- **THEN** 停用項目無 hover 回饋且不可執行；可用元件保留可見鍵盤焦點

### Requirement: 本地快取用量
系統 SHALL 在「設定」頁提供「本地快取」區塊，以易讀單位顯示瀏覽器估計的已用空間／可用上限；瀏覽器提供分項用量時 SHALL 列出已回報的 IndexedDB 與 Cache Storage 用量。無法取得估計值時 MUST 顯示「此瀏覽器無法取得快取用量」，未知分項不得當作零。

#### Scenario: 依瀏覽器能力顯示用量
- **自動化驗證**: `UI-11`；Playwright 注入總量、有／無／部分分項、零用量、缺少 API 與拒絕回應，斷言易讀總量、分項顯示與省略、載入及失敗提示，並在重新進入設定後取得最新值。
- **WHEN** 使用者開啟設定頁，瀏覽器提供儲存估計或無法取得估計
- **THEN** 顯示「本地快取」及目前已用空間／可用上限，僅列出已回報的分項；不支援或失敗時顯示無法取得提示，重新進入設定時重新估計
