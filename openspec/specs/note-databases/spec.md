# note-databases Specification

## Purpose

提供以 Notion 核心概念整理筆記的資料庫頁面：每筆資料皆保有完整筆記正文，使用者能自訂欄位並以多個儲存檢視依主題、標籤及日期找回內容，同時保護既有階層、私人資料與保存狀態。

## Requirements

### Requirement: 資料庫頁面與筆記歸屬

系統 SHALL 允許在最上層或一般筆記下建立具標題的資料庫頁面；直接隸屬筆記為資料列，可新增或移入既有筆記、移出及開啟完整正文。資料庫內不再直接建立資料庫，日記不移入。資料庫刪除及還原 SHALL 沿用子樹生命週期，不復活事先刪除的資料列。

#### Scenario: 建立與整理筆記
- **WHEN** 使用者建立資料庫、新增筆記並移入及移出既有筆記
- **THEN** 資料庫列表、側欄及原頁面 ID 一致，正文保持完整，資料列開啟後可返回資料庫
- **自動化驗證**: `DB-01`；Playwright：操作建立與移動，斷言 URL、parent_id、列集合及正文重開內容。

#### Scenario: 資料庫垃圾桶
- **WHEN** 先刪除一列，再刪除並還原資料庫
- **THEN** 有效列與欄位恢復，先前刪除列仍留垃圾桶
- **自動化驗證**: `DB-02`；Playwright：建立兩列並刪除／還原，斷言可見列、刪除標記、欄位及正文。

### Requirement: 自訂欄位與筆記屬性

系統 SHALL 支援文字、數字、日期、單選、多選、勾選與網址欄位，以及不可移除的標題及唯讀建立／更新時間。欄位可新增、重新命名、排列與刪除，選項可管理；修改類型時不得默默丟棄不相容資料。欄位值可在表格及筆記正文上方編輯，重新命名不改變值。刪除欄位需確認；隱藏欄位不刪值。網址僅允許 HTTP／HTTPS。

#### Scenario: 欄位往返
- **WHEN** 使用者建立各類欄位、填值、重新命名與調整選項後重開
- **THEN** 型別和值保持正確，筆記頁及表格一致，建立／更新時間唯讀
- **自動化驗證**: `DB-03`；Playwright：逐類填值並重開、由筆記頁修改，斷言 API 與兩個入口的欄位值、標題及時間。

#### Scenario: 非法值及安全欄位修改
- **WHEN** 使用者提交無效日期、數字、網址、未知欄位／選項或不相容型別變更
- **THEN** 系統拒絕並保留原資料，刪除欄位取消不改變設定
- **自動化驗證**: `DB-04`；Playwright：參數化非法 API 輸入及欄位刪除確認，斷言非成功回應、原值與取消後設定一致。

### Requirement: 表格清單與儲存檢視

系統 SHALL 提供表格及清單檢視，並能新增、命名、切換、修改與刪除儲存檢視；至少保留一個檢視。各檢視獨立保存顯示欄位順序、篩選及排序。篩選支援全部／任一條件、相等／不等／包含／空值／非空／大於／小於；運算子依型別限定。排序支援多個欄位與升降序，穩定呈現相同值。資料庫內搜尋依筆記標題。

#### Scenario: 檢視保存與切換
- **WHEN** 使用者建立兩個不同檢視並設定篩選、排序及顯示欄位後重開
- **THEN** 檢視設定保留，切換後列集合及欄位順序符合各自設定，不複製筆記
- **自動化驗證**: `DB-05`；Playwright：以三列 fixture 操作表格／清單、AND／OR、數字排序與隱藏欄位，斷言列集合、順序、重開設定及頁面數量。

### Requirement: 私有連線保存與跨裝置更新

系統 MUST 驗證登入、來源、擁有者、有效頁面及目前欄位設定，拒絕垃圾桶子樹及還原前世代寫入。欄位與檢視修改須連線並等待成功回應，失敗保留輸入供重試，不宣稱已儲存；正文維持既有離線能力。不同欄位的併發更新不得互相覆蓋；不同檢視的獨立修改 SHALL 合併保留，相同檢視及不相容欄位設定衝突 MUST 拒絕。前景且連線中的另一裝置 SHALL 在有界時間內讀取保存結果；背景分頁 SHALL 暫停資料庫輪詢，恢復可見立即補讀。

#### Scenario: 保存失敗與併發
- **WHEN** 保存請求失敗、兩裝置修改不同欄位或同一檢視的衝突設定
- **THEN** 失敗仍可重試，合法不同欄位皆保留，相同檢視衝突被拒絕，另一裝置可取得成功值
- **自動化驗證**: `DB-06`；Playwright：攔截保存失敗、兩 context 併發及設定衝突，斷言草稿、錯誤狀態、兩欄合併與第二裝置更新。

#### Scenario: 拒絕越權與離線修改
- **WHEN** 未登入、跨來源、無權限、垃圾桶或舊世代請求修改，或裝置斷網
- **THEN** 拒絕無效寫入；離線仍可編輯已下載正文，屬性提示連線限制
- **自動化驗證**: `DB-07`；Playwright：參數化權限／刪除／世代 API、離線已下載筆記，斷言拒絕、原資料不變、屬性限制與正文可編輯。

#### Scenario: 背景暫停與條件更新
- **WHEN** 前景分頁重複讀取未變更資料庫、子列或設定改變，或分頁轉背景再回前景
- **THEN** 未變更回無本文 304；資料變更使版本失效並取得新值；背景沒有輪詢請求，恢復可見立即讀取；垃圾桶祖先及還原鎖定仍拒絕讀取
- **自動化驗證**: `DB-11`；Playwright 與 Workers：控制 visibilityState、條件請求及頁面生命週期，斷言請求次數、ETag、304 空本文、子列更新與不可見祖先拒絕。

#### Scenario: 獨立檢視併發
- **WHEN** 兩裝置以相同原始版本修改不同檢視，或相同檢視產生競爭修改
- **THEN** 不同檢視修改皆保留；相同檢視衝突回 409 且保留原成功結果，單純檢視修改不因資料列屬性更新互相拒絕
- **自動化驗證**: `DB-12`；Playwright 與 Workers：以同一 previous 提交不同及相同檢視修改，斷言合併設定、409、原值與列更新結果。

### Requirement: 手機與鍵盤操作

系統 SHALL 讓主要建立、欄位編輯與檢視操作可由鍵盤及手機觸控完成，手機表格限制於自身捲動容器，不使工作區水平溢出。

#### Scenario: 響應式資料庫
- **WHEN** 使用者在桌面鍵盤或手機操作資料庫及筆記欄位
- **THEN** 操作可達、焦點可用、長表格不使整頁溢出
- **自動化驗證**: `DB-08`；Playwright：三瀏覽器執行核心操作，斷言 375px 頁面幾何、控制標籤及鍵盤提交。
