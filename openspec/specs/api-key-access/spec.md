# API key 與內容介面

## Purpose

讓擁有者從設定頁管理可再次顯示的個人 API key，以一般 HTTP 與 JSON 讀寫自己的筆記與日記，同時保留帳號隔離、憑證撤銷、正文持久保存及多人裝置修改衝突的安全保護。

## Requirements

### Requirement: 可再次顯示的 key 管理

系統 SHALL 讓已登入使用者命名、建立、列出、再次顯示、複製及撤銷自己的 API key。列表預設遮罩，每帳號最多 20 把，名稱 1～80 字元，預設不過期。只有有效網站登入能管理 key；所有回應 MUST 禁止快取，憑證不可寫入本機持久儲存或產品匯出。

#### Scenario: 建立與再次查看

- **WHEN** 使用者建立 key、隱藏後再次顯示，或離開設定再返回
- **THEN** 可取得同一把完整 key，列表不自動暴露 key，複製有成功／失敗回饋
- **自動化驗證**: `KEY-01`；Workers＋Playwright：建立具名 key，兩次 reveal 相同，回傳 no-store，資料庫沒有明文；桌面與手機檢查遮罩、重入、複製及空白名稱拒絕。

#### Scenario: 管理權限與撤銷

- **WHEN** 未登入、跨來源、其他帳號或 API key 嘗試管理憑證，或使用已撤銷 key
- **THEN** 請求被拒絕；撤銷後不能再次顯示或授權新請求；不得影響其他 key
- **自動化驗證**: `KEY-02`；Workers＋Playwright：參數化上述權限、兩把 key 與撤銷，斷言 401／403／404、跨 owner 無資料與獨立有效性。

### Requirement: 帳號專屬內容 API

系統 SHALL 用 Bearer key 開放自己的筆記／日記讀取、搜尋、建立、標題與階層修改。MUST 忽略外來 owner 宣告，排除垃圾桶與其他帳號；不開放刪除、備份、還原、圖片上傳或憑證管理，錯誤 key 不得回退使用 cookie。

#### Scenario: API 內容操作與範圍

- **WHEN** 外部程式用有效 key 操作允許的路由，或偽造 owner／呼叫禁止路由
- **THEN** 只對自己的可見資料生效；同日期日記維持唯一；禁止路由與錯誤憑證均拒絕
- **自動化驗證**: `KEY-03`；Workers：無 Origin 的 Bearer 請求建立、列表、搜尋、改名、移動、日記；檢查跨帳號、垃圾桶、路由 allowlist 與無效 key 不降級。

### Requirement: JSON 正文安全往返

系統 SHALL 提供區塊 JSON 正文讀取與更新，保持格式、階層及正文同步。更新 MUST 帶讀取時的 ETag，缺少時 428、已過時時 412；成功只在持久保存後回覆且在線裝置收到更新。無效／超限正文、刪除／還原中頁面、錯誤世代及失效 key MUST 拒絕且保留原內容。

#### Scenario: 正文往返與同步

- **WHEN** 使用者經 API 讀取後帶有效 ETag 更新 JSON 正文
- **THEN** 重啟後仍可讀到相同正文，網站顯示更新，搜尋可找回文字
- **自動化驗證**: `KEY-04`；Workers＋Playwright：斷言 JSON 多型區塊往返、服務重啟、即時網站可見與網站修改後 API 讀取。

#### Scenario: 過時或失敗更新

- **WHEN** PUT 缺少／過時 ETag、兩個請求同版本競爭、超限／格式錯誤、跨帳號圖片或持久保存故障
- **THEN** 回應錯誤、不成功廣播且原內容保留；同版本競爭最多一筆成功
- **自動化驗證**: `KEY-05`；Workers：參數化異常與故障注入，斷言狀態碼、持久內容及併發成功數。

### Requirement: 備份與發布隔離

系統 MUST 排除 API key 的產品備份／匯出；還原內容不得復活撤銷 key。部署 SHALL 從隔離 worktree 已提交版本完成，保留其他工作區狀態。

#### Scenario: 備份與正式發布

- **WHEN** 建立備份、撤銷 key、還原並發布新版本
- **THEN** 備份無憑證、舊 key 無效；正式端新 API 正常且未授權請求拒絕
- **自動化驗證**: `KEY-06`；Workers 備份還原測試＋正式 HTTP 自動化：掃描備份檔案、斷言撤銷不復活，正式確認新資產與 API 的 401、有效 key 內容往返及撤銷。
