# 頁面與日記開發

本輪完成 OpenSpec 5.1、5.2，對應 PAGE-01～08。登入仍使用 [既有本機寄件匣](auth-development.md)，沒有接入正式寄信或部署。

## 使用入口

分別執行 `npm run dev` 與 `npm run dev:test-worker`，開啟 `http://127.0.0.1:5173/`。登入後開今天的日記；桌面提供側邊導覽，手機從「導覽」開啟操作。

導覽提供今天、日期補寫、月份日記列表、階層筆記、搜尋與垃圾桶。新增筆記後可修改標題；「頁面操作」可新增子頁、移動或移到垃圾桶。路徑可返回上層。日記日期獨立於標題與實際時間；同一天包含垃圾桶也只保留一篇，開啟已刪日記時還原原篇。

## 資料與異動

[0001.sql](../migrations/0001.sql) 保留原始 schema；新增 [0002.sql](../migrations/0002.sql) 的操作意圖與子樹成員表。測試 runtime 自動套用兩份 migration；不執行雲端 migration。所有 API 從 server session 取得 owner，新增／標題／移動要求連線，並沿用來源與請求大小檢查。

新增／移動使用 D1 單一條件 SQL，檢查有效上層、owner、筆記類型、祖先可見性及循環；併發互移不會形成封閉循環。移到最上層必須明確傳入 `parent_id: null`，缺值不得冒充移動。標題限 1～200 字元；日期必須為實際有效日曆日期。

垃圾桶只標記被操作的根節點，子樹依祖先隱藏；還原不清除先前單獨刪除的子頁。刪除／還原先保存操作意圖與固定成員，再等房間排空並持久暫停，修改 D1 標記後解除暫停，最後結束意圖。失敗保留處理中狀態；相關 API／列表／同步拒絕或隱藏未完成狀態，重送同一操作可繼續。改變結構期間不接受其他結構異動，防止成員清單失效。

已確認的 Yjs 更新與圖片原檔不因垃圾桶刪除；還原使用原世代與原房間。PAGE-06 以固定 R2 圖片／Yjs 引用 fixture 斷言原檔相同，沒有把 fixture 存取當成私有資產服務驗收。

## 搜尋與本機保護

正式房間從持久 Yjs 狀態抽出文字，記錄 owner／page／generation／checkpoint，寫入可重建的 D1 索引。搜尋比對標題與中文內文子字串，排除垃圾桶子樹、其他 owner、處理中頁面及不相容索引；百分號等字元當作 literal。索引失敗不否定已保存正文，可由後續更新、喚醒或內部重建重試。舊檢查點與舊世代不能覆蓋新索引，正文不因搜尋改寫。

導覽與刪頁前先透過既有 IndexedDB 保存函式保留草稿。保存失敗即停留原頁，不繼續導覽或刪除；權限重驗斷線時捕捉拒絕並顯示連線失敗，草稿仍可保留。此範圍不取代後續完整離線啟動與同步整合驗收。

## 自動化驗證

```sh
npm test
npm run test:spec-coverage -- --pages
npm run test:spec-coverage -- --auth
npm run test:spec-coverage -- --probe
npm run check
npm run build
npm run check:spec
```

`--pages` 直接讀取頁面 spec，要求八個 Workers 結果與六個瀏覽器情境在三種 engine 的結果。缺漏、重複、skip 或失敗都不是完成。首次 Red、Green、Refactor 與限制見 [TDD 證據](tdd/README.md)。正式私有圖片、備份、覆蓋還原世代切換與部署仍在後續範圍；手機仍使用瀏覽器模擬，沿用單次 Yjs 更新 512 KiB 的既有界線。
